# J-dashboard

Дашборд моей рекламы Amazon Ads: читает отчёты API, складывает их в SQLite и
публикует статический сайт на GitHub Pages — как кабинет Amazon, но только с
нужными разрезами и без лишнего.

- Сайт: `https://eugene55555.github.io/J-dashboard/`
- Обновление данных — **по запросу владельца**: кнопки в интерфейсе нет
  намеренно, свежие отчёты подтягивает агент и пересобирает статику.
- В репозитории — только мой кабинет. Второй аккаунт подключается отдельной
  записью в `data/accounts.json`, если когда-нибудь понадобится.

Данные не правятся: дашборд только читает и показывает. Реклама из него не
меняется.

## Что внутри

| Раздел | Что показывает |
|---|---|
| **Обзор** | KPI за период (расход, продажи, ACOS, заказы, клики, показы), динамика по дням, топ кампаний по расходу, сравнение с предыдущим периодом |
| **Кампании** | бюджет, статус, стратегия ставок, надбавка TOS, показы/клики/CTR/CPC/заказы/продажи/ACOS/ROAS |
| **Ключи и цели** | таргеты и ключи, тип совпадения, ставка (своя или из группы), статус, результаты; отдельная вкладка негативов |
| **Поисковые термины** | реальные запросы покупателей, фильтр «только с заказами» |
| **Размещения** | Top of Search / Rest of Search / Product Pages по кампаниям |
| **Товары** | эффективность по ASIN |
| **Изменения** | журнал: что, когда и как менялось — бюджет, ставка, статус, надбавки, ключи, негативы |
| **Данные** | покрытие по дням, запуски, кнопка повторного сканирования папки |

Фильтры: 1 / 7 / 14 / 30 дней, этот и прошлый месяц, свой диапазон,
одна или несколько кампаний.

## Архитектура

```
Amazon Ads API ──► data/inbox/ ──► ingest (распознавание + нормализация) ──► data/dashboard.db ──► FastAPI ──► браузер
     ▲                                    ▲
     └── ingest.amazon / ingest.history ──┘   (сырые файлы остаются как есть)
```

- `ingest/amazon.py` — выгрузка отчётов и снимков настроек в папку.
- `ingest/history.py` — история изменений Amazon (`POST /history`).
- `ingest/load.py` — распознавание файлов, запись фактов, дифф настроек в журнал.
- `app/` — API и интерфейс; `app/queries.py` — вся аналитика.
- `data/inbox/` — «положи файлы сюда»; `data/dashboard.db` — база.

## Два режима

| Режим | Что это | Как запускается |
|---|---|---|
| **Локальный сервер** | FastAPI + SQLite, фильтры считаются SQL | `./run.sh` |
| **Статический сайт** | `docs/` с `data.json`, все фильтры считаются в браузере | `python3 build_static.py --out docs` |

Оба используют один и тот же интерфейс: `app/static/app.js` переключается
между API и локальными данными автоматически.

## Быстрый старт

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                 # пароль и секрет
cp accounts.example.json data/accounts.json   # список кабинетов
./run.sh                             # http://127.0.0.1:8080
```

Кабинеты описываются в `data/accounts.json` (в git не попадает):

```json
[
  {"id": "eugene", "label": "Eugene · Amazon Ads US",
   "db": "data/accounts/eugene.db", "profile_id": "2346284607821433"},
  {"id": "dimon", "label": "Dimon · Amazon Ads US",
   "db": "data/accounts/dimon.db", "profile_id": "1794615056359259"}
]
```

Загрузить уже скачанные отчёты в конкретный кабинет:

```bash
python3 -m ingest.cli scan  data/inbox_eugene
python3 -m ingest.cli load  data/inbox_eugene --db data/accounts/eugene.db
```

## Как добавлять отчёты

Кидайте в `data/inbox` **любые** отчёты Amazon Ads — CSV или JSON, с любыми
именами. Тип определяется по составу полей:

| Что в файле | Куда попадёт |
|---|---|
| `date.value` + `campaign.id` без `adGroup.id` | дневные итоги по кампаниям |
| `date.value` + `adGroup.id` | группы, цели, термины, размещения, товары — сразу во все разрезы, которые поддерживает файл |
| `campaignId` + `budget` | кампании (бюджет, статус, стратегия, надбавки) |
| `adGroupId` + `defaultBid` | группы объявлений |
| `targetId` + `bid` | цели и таргеты |
| `targetId` без `bid` | негативные цели |
| `keywordId` + `NEGATIVE_*` | негативные ключи (кампании или группы) |
| `keywordId` + `bid` | ключевые слова |
| `adId` + `asin` | объявления |
| `changeType` + `timestamp` | история изменений Amazon |
| `change_id` + `field` | готовый журнал изменений |

После добавления файлов нажмите «Обновить» или «Пересканировать inbox» в
разделе «Данные».

## Вход по паролю

Сайт статический, поэтому защита сделана шифрованием: `docs/data.enc.json`
зашифрован AES-256-GCM, ключ выводится из логина и пароля через PBKDF2-SHA256
(200 000 итераций). Без пароля в браузере остаются только оболочка и стили —
ни расходов, ни названий кампаний, ни терминов.

```bash
python3 build_static.py --account eugene --out docs \
  --login eugene --password 'новый-пароль'
git add docs && git commit -m "data: обновление" && git push
```

- Пароль нигде не хранится на сервере: он есть только у владельца и в его
  браузере (sessionStorage на время сессии).
- Сменить пароль = пересобрать с новым `--password` и запушить.
- `--password ""` (или без флага) снова делает сборку открытой.
- Ограничение: страница и скрипты публичны, секрет — только в данных. Слабый
  пароль можно перебрать офлайн по `data.enc.json`, поэтому пароль должен быть
  длинным.

## Публикация на GitHub Pages

```bash
python3 build_static.py --account eugene --out docs
git add docs && git commit -m "data: обновление на $(date +%F)" && git push
```

Pages настроен на ветку `main`, папку `/docs`. После пуша сборка занимает
около минуты, сайт обновляется сам.

**Важно:** GitHub Pages не умеет серверные пароли. Защита — шифрование данных
(см. раздел «Вход по паролю»); `robots.txt` и `noindex` дополнительно закрывают
сайт от поисковиков.

## Синхронизация с Amazon

Ключи должны лежать на том хосте, которому принадлежит аккаунт
(`~/hermes-workspace/ads-amazon-key/secrets.env`). Дашборд сам секреты не хранит.

```bash
# отчёты за 60 дней + свежие настройки в отдельную папку кабинета
python3 -m ingest.amazon --days 60 --out data/inbox_eugene

# история изменений за 88 дней (долго: пауза 180 с между запросами)
nohup python3 -m ingest.history --days 88 --out data/inbox_eugene > history.log 2>&1 &

# разложить по базе этого кабинета
python3 -m ingest.cli load data/inbox_eugene --db data/accounts/eugene.db
```

Кабинет определяется ключом `profile_id_us` в `secrets.env`: один хост с
ключами — один аккаунт. Если кабинеты на разных серверах, выгрузка идёт там,
где лежат ключи, а загрузка — там, где живёт дашборд.

Обновление запускаю я по твоему запросу: выгрузка → загрузка в базу →
пересборка `docs/` → пуш. Кнопки в интерфейсе нет.

Расписание в cron не обязательно, но если понадобится:

```cron
15 6 * * * cd /opt/amazon-ads-dashboard && ./sync.sh >> logs/sync.log 2>&1
```

`sync.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")"
python3 -m ingest.amazon --days 3 --out data/inbox_eugene
python3 -m ingest.cli load data/inbox_eugene --db data/accounts/eugene.db
```

Окно `--days 3` (а не 1) нужно потому, что Amazon доуточняет атрибуцию
несколько дней: вчерашние цифры дозревают.

## Развёртывание

### systemd

```ini
[Unit]
Description=J-dashboard
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/opt/j-dashboard
EnvironmentFile=/opt/j-dashboard/.env
ExecStart=/usr/bin/python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8080
Restart=always

[Install]
WantedBy=multi-user.target
```

Снаружи — nginx с HTTPS и `J_SECURE_COOKIE=true`.

### Docker

```bash
docker build -t j-dashboard .
docker run -d --name j-dashboard -p 127.0.0.1:8080:8080 \
  -e J_PASSWORD='...' -e J_SECRET='...' \
  -v "$PWD/data:/app/data" j-dashboard
```

## Несколько кабинетов (опционально)

- Один кабинет = один файл базы. Переключатель появляется, только если в
  `data/accounts.json` больше одной записи.
- Ключи разных аккаунтов нельзя держать на одном хосте: у каждого владельца свой
  сервер и свой `secrets.env`.
- Сейчас подключён только мой кабинет: `data/accounts/eugene.db`.

## Безопасность

- `J_PASSWORD` включает вход по паролю; сессия — подписанная HMAC-cookie.
- `J_SECRET` обязателен вместе с паролем, иначе сессии сбрасываются при рестарте.
- Ключи Amazon и `.env` не попадают в git (`.gitignore`).
- Наружу — только через HTTPS; `J_SECURE_COOKIE=true`.

## Честные ограничения

- **История Amazon ограничена**: отчёты Reporting v1 — до 24 месяцев по дням,
  `POST /history` — 90 дней и только уровень кампании. Всё, что нужно хранить
  дольше, должно быть выгружено и сохранено заранее.
- **Первый импорт не создаёт событий «создан»** — иначе журнал начинался бы с
  тысяч записей. Дальше новые объекты логируются.
- **Дифф снимков видит только факт изменения между синхронизациями.** Если
  ставку меняли дважды между запусками, останется последнее значение.
- **Ставки и ключи в `POST /history` не приходят** — только кампания (бюджет,
  статус, имя, надбавки). Правки целей видны как разница снимков и как события
  агента.
- **Отчёт уровня кампании и детальный отчёт могут расходиться** в показах на
  свежих днях. Это разница источников, а не ошибка: деньги берутся из отчёта
  кампаний, остальные разрезы — из детального.
- **Даты в полях ввода** показываются в формате браузера (в Chrome — MM/DD/YYYY),
  в интерфейсе — DD.MM.YYYY.

## Структура

```
build_static.py  сборка docs/ для GitHub Pages
app/
  main.py        FastAPI: API, кабинеты, авторизация, статика
  queries.py     SQL-аналитика
  config.py      настройки из окружения
  static/        интерфейс (без сборки и CDN); local.js — расчёты в браузере
ingest/
  detect.py      распознавание файлов
  load.py        загрузка, дифф настроек, журнал
  amazon.py      выгрузка отчётов и настроек
  history.py     выгрузка истории изменений
  cli.py         scan / load
tests/           unittest, без внешних зависимостей
```
